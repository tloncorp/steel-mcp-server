## Dependency notes

- Plan 001 is standalone. It deliberately keeps MCP `input_required` as the safety
  gate and does not depend on an upstream Codex change.
- Plan 003 is first because batching is already positively advertised but currently
  bypasses detected login/CAPTCHA handling. It has no functional dependency on click
  recovery hardening.
- Plan 002 completes and validates the interaction hardening already present in the
  working tree. Its broader recovery-episode state is gated on a deterministic
  sibling/wrapper reproduction so unrelated blocked controls are not conflated.
- Plan 005 is the core composition and deployment gate: it refines the already-positive
  batch guidance, verifies one preserved stateful session through handoff, evaluates a
  sanitized model-visible trace, installs a fresh MCPB, and reruns Claude Desktop only
  after Plans 002 and 003 are green.
- Plan 004 is optional and is not a prerequisite for the core fix. It changes the
  abandoned-session billing/concurrency envelope and can protect a quiet continuation
  only when enough immutable hard runway remains.
- Plan 006 is independent observability work. It lets future support distinguish idle,
  hard-expiry, explicit release and stream shutdown without reading private host caches.
- Plan 007 follows Plan 005 (and therefore Plans 002 and 003) because it changes the
  same session, instruction, registry and handoff surfaces. It adds only one
  model-visible tool and keeps the existing 17,000-byte browse ceiling. Refresh it
  against optional Plan 004 or independent Plan 006 if either lands first.

## Findings considered and rejected

- Treat Codex as inline-viewer-capable based on its client name: rejected because
  capability support must come from the request or initialize declaration for the
  observed wire era; client-name inference would create a protocol fork.
- Remove `input_required` so Hand back alone resumes the agent: rejected because it
  removes the formal pause that prevents the agent from acting while a person is in
  control.
- Make the viewer's Hand back button complete the pending elicitation: rejected for
  this plan because the MCP Apps bridge exposes no portable operation for an app to
  accept a separate host-owned MRTR input request.
- Increase only the 15-minute hard-session default: rejected because Launch accounts
  clamp it to 15 minutes, so it cannot repair this observed run.
- Treat `browser_session_handoff` as a workaround for Claude's tool-use cap: rejected.
  The server cannot see Claude's remaining host budget, and handoff cannot extend the
  immutable hard expiry.
- Promise that a saved profile or replacement session preserves a cart: rejected.
  Profiles load a stored baseline but this server does not write session changes back;
  cart persistence is guaranteed only in the same live browser.
- Suppress the request for a `Continue` turn: rejected because once the host returns
  `stop_reason=tool_use_limit`, the model cannot make another MCP call.
- Add a separate `task_duration_hint`: rejected as redundant with `timeout_ms`; the
  account maximum and returned `expires_at` remain authoritative.
- Read Claude Desktop IndexedDB from CI or infer model-visible calls from raw MCP traffic:
  rejected as private, host-specific, and unable to distinguish app-only viewer calls
  reliably. Plan 005 uses sanitized contract tests plus one explicit Desktop dogfood gate.
- Free-form dogfood notes as the only acceptance evidence: rejected. Plan 005 stores a
  sanitized, schema-validated trace containing tool names, relative timings, stop
  reasons, error codes and booleans only.
- Fold hit-test remote-object cleanup into the blocker-loop fix: deferred as an
  independent P2 performance task. It is real cleanup debt but did not cause this run.
- Add separate profile-list, credential-list, proxy-list and recipe tools: rejected.
  One deterministic `browser_session_options` result can carry safe candidates and a
  signed configuration while adding only one model-visible tool.
- Put account candidates in dynamic tool enums or `tools/list`: rejected because the
  list is publicly cached and must stay deterministic and principal-independent.
- Mirror the complete Steel Sessions schema or accept generic configuration JSON:
  rejected because it inflates the permanent prompt and exposes settings that conflict
  with viewer/handoff safety. Supported advanced settings travel in a narrow signed
  plan instead.
- Expose credential/profile CRUD: rejected because secret values and browser archives
  must never traverse model context; provisioning remains out of band and profile
  persistence uses Steel's session lifecycle.
- Add fixed dedicated-IP discovery now: rejected because the checked public Steel
  OpenAPI has no metadata list endpoint that lets this MCP safely find a stable ID.
